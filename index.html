HIAAC-Rec: An Open-Source Toolkit for Synchronized Multimodal Data Collection, Annotation, and Face Anonymization

Beatriz V. P. Moura1,2, Marcos M. Nunes1,2, Gustavo P. C. P. da Luz1,2, Miguel B. Simões1,2, Victor Wu1,2, Nicolas H. Silva1,2, Jaime A. D. Vargas1,2, Amparo D. Muñoz1,3, Saulo A. Moraes1,3, Felipe A. de Paula Santos1,3, Fabio Grassiotto1,3, Anderson Rocha1,2, Levy Boccato1,2, Edson Borin1,2,*
1Hub for Artificial Intelligence and Cognitive Architectures (H.IAAC), Campinas, Brazil
2University of Campinas (UNICAMP), Campinas, Brazil  •  3Instituto de Pesquisas Eldorado, Campinas, Brazil
*Corresponding author: borin@unicamp.br
Abstract

This work presents HIAAC-Rec, an open-source toolkit for building high-quality multimodal datasets for Human Activity Recognition (HAR). Unlike prior work, which mostly releases only the collected dataset or lightweight pre-processing scripts, the proposed toolkit integrates, in a single pipeline: a smartphone-based data acquisition application, a server-side backend for data synchronization and processing, a face-masking anonymization application, an interactive time-series labeling interface, and a multi-annotator visualization interface. The toolkit was validated with six smartphones producing 45 sensor channels at 10 and 100 Hz alongside 30 fps video. Experiments demonstrate an inter-device lag below half a sampling period (largest absolute mean lag of 3.75 ms with no relative drift), and face anonymization achieving 94.59% automatic masking coverage, reaching full agreement through manual auditing across 25 annotated videos.

Android (Java / CameraX) • Mobile Client

HIAAC-Rec-App

The mobile acquisition frontend. Directly interfaces with Android hardware sensor APIs using dedicated high-priority threads (AIDL), capturing inertial (accelerometer, gyroscope, linear acceleration, magnetometer, gravity), environmental (ambient temperature, light, proximity), and location (GPS) data at configurable rates from 1 Hz up to 200 Hz, synchronized with nominal 30 FPS video via CameraX. Implements Cristian's algorithm client pings to establish millisecond-precision clock offset before recording.

  • Configurable sampling rates up to 200 Hz via dedicated background threads without dropping camera frames.
  • Quality assurance statistics screen displays expected vs collected samples, valid vs discarded ratios, and clock jitter.
  • Continuous device telemetry profiling (CPU usage %, RAM memory, and battery capacity).
Figure 6: Server interface for experiment monitoring, data inspection, and synchronized sensor-video playback.
Node.js Preprocessor (:8080) • Python Postprocessor (:7998)

HIAAC-Rec-SyncServer

The central synchronization and automated processing backend. The Node.js Preprocessor (:8080) manages experiment configurations, provides Cristian's algorithm reference clock endpoint, receives multi-device uploads, and renders an on-site participant inspection portal with D3.js. The Python Postprocessor daemon (:7998) cleans raw CSVs, trims sensor streams to exact video start/end boundaries, shifts the timeline to video start (t = 0), and triggers automated face anonymization.

  • Preprocessor REST APIs (/api/file, /api/video, /api/time) handle authentication and multi-device ingestion.
  • Postprocessor watchdog trims sensor records to exact video boundaries and standardizes per-sensor CSVs.
  • Web inspection portal enables immediate synchronized playback for on-site participant verification and consent.
Figure 8: HIAAC-Rec-Masking-Studio manual auditing interface and timeline tracking.
FastAPI • ONNX Runtime / OpenCV (:8000)

HIAAC-Rec-Masking-Studio

Privacy-preserving video face anonymization tool combining deep-learning tracking with human verification. It runs an automatic head detector (YOLOv7-tiny-head ONNX) achieving 94.59% automatic masking coverage across 25 benchmarked videos, followed by keyframe auditing passes to guarantee full GDPR/LGPD compliance.

  • Multi-pass auditing trail: Pass 0 (automatic tracking) followed by reproducible manual review passes (Manual 1, Manual 2...).
  • Track management allows ending, reactivating, and adjusting bounding boxes frame-by-frame.
  • Render overlay modes: Gaussian blur, mosaic/pixelation, or opaque solid fill, with WebSocket progress streaming.
Figure 10: HIAAC-Rec-Labeler time-series annotation charts synchronized with video.
Dash / Plotly • Python (:8050)

HIAAC-Rec-Labeler

Synchronized time-series annotation interface designed specifically for Human Activity Recognition (HAR). It renders panoramic and detailed zooming charts linked to video playback via a draggable orange time marker at millisecond precision, enabling annotators to inspect raw acceleration signatures while observing the participant's actions.

  • Standardized 'ends-at' convention (-1 for segment initiation/unassigned, activity label for termination).
  • Dynamic activity label management via ⚙ gear button, persisted into session manifests and YAML config.
  • Bidirectional timeline seeking: moving on the signal updates video frames instantaneously.
Figure 11: HIAAC-Rec-Viewer multi-annotator alignment and consensus evaluation.
Dash / Plotly • Python (:8052)

HIAAC-Rec-Viewer

Multi-annotator inspection and consensus consolidation environment. Allows loading independent annotation files from multiple researchers, comparing alignment against the synchronized video and sensor signals, and computing consolidated ground-truth tracks using configurable agreement algorithms.

  • Three consensus strategies: Union (broadest coverage), Intersection (strict agreement), and Majority voting.
  • Visual disagreement highlighting in color-coded bands to detect ambiguous movement transitions across annotators.
  • One-click export of consolidated session packages with manifest, video, sensors, and labels.
Empirical Results

Experimental Validation from the Paper

Quantitative and qualitative evaluations of temporal synchronization and face anonymization conducted with five body-worn smartphones and a dedicated video device.

⏱️ Inter-Device Temporal Synchronization

Five smartphones were taped into a rigid stack (Annotator, Right Pocket, Left Pocket, Right Hand, Crossbody Bag) and subjected to identical physical motion (horizontal displacement, orientation changes, dragging, and lifting) at 10Hz and 100Hz, while video was recorded simultaneously.

Figure 15: Linear acceleration magnitude recorded by the Right Pocket device over the 100Hz run (17 min). Annotated activity windows correspond to controlled displacement events separated by rest.

Key Finding: Across all annotated windows, the largest absolute mean lag is only 3.75 ms (well below half a sampling period $T_s / 2 = 5\text{ ms}$ at 100Hz). Furthermore, comparing waveforms at the beginning and end of the collection confirms zero relative drift over time.

🎭 Face Anonymization Coverage & Auditing

Evaluated on 25 recordings (1,080,530 reference bounding boxes) processed through four successive stages: Pass 0 automated tracking (YOLOv7-tiny-head), two independent annotator review passes, and final validation.

Figure 12: Qualitative comparison across models: Manual label, YOLOv7-tiny-head (tight head masks), YOLOv11m, YOLOv26m-pose, YOLOv11x-pose, and MediaPipe (frontal only).

Key Finding: Automatic detection recovers 94.59% of all participant faces at 12.7 FPS, while successive human auditing passes progressively eliminate missing detections to guarantee GDPR/LGPD compliance.
